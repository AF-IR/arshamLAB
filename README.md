# Arsham Lab — آرشام لب | ابزارهای کاربردی آرشام

پلتفرم حرفه‌ای، سریع و سئو محور برای ارائه **ابزارهای کاربردی و رایگان آنلاین** — بدون نیاز به ثبت‌نام، با پردازش محلی در مرورگر.

- **فریم‌ورک:** Next.js 16 (App Router) + React 19 + TypeScript 5 (strict)
- **استایل:** Tailwind CSS 4 + فونت وزیرمتن (self-hosted با next/font)
- **زبان و جهت:** فارسی — `lang="fa"` و `dir="rtl"`
- **استقرار:** سازگار با Vercel (output: standalone)

---

## ۱. اجرای محلی

```bash
# نصب وابستگی‌ها
bun install        # یا: npm install

# اجرای محلی (http://localhost:3000)
bun run dev

# بررسی انواع TypeScript
bun run typecheck

# بررسی کیفیت کد (ESLint)
bun run lint

# اجرای تست‌های واحد منطق ابزارها
bun test

# Build تولیدی
bun run build

# اجرای نسخه تولیدی
bun run start
```

> برای بررسی Build بدون دست‌زدن به سرور توسعه:
> `NEXT_DIST_DIR=.next-prod bunx next build` (مسیر خروجی جدا ساخته می‌شود و بعد از بررسی می‌توانید `.next-prod` را حذف کنید).

## ۳. متغیرهای محیطی

نمونه کامل در `.env.example` موجود است.

| متغیر | توضیح |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | **الزامی در تولید.** دامنه اصلی مثل `https://arshamlab.com`؛ همه Canonical، Open Graph و Sitemap از همین ساخته می‌شوند. در توسعه اگر تنظیم نشود `http://localhost:3000` استفاده می‌شود تا URLهای اشتباه ایندکس نشوند. |
| `NEXT_PUBLIC_CONTACT_EMAIL` | ایمیل تماس؛ در صورت تنظیم، فرم صفحه تماس فعال می‌شود (در غیر این صورت فرم غیرفعال و بدون اطلاعات جعلی نمایش داده می‌شود). |
| `NEXT_PUBLIC_ADS_ENABLED` | `true` = جایگاه‌های تبلیغاتی رندر می‌شوند. پیش‌فرض: غیرفعال (هیچ چیزی رندر نمی‌شود). |
| `NEXT_PUBLIC_AD_HOME_HERO_CODE` | کد HTML جایگاه تبلیغ زیر Hero صفحه اصلی. |
| `NEXT_PUBLIC_AD_TOOL_IN_CONTENT_CODE` | کد HTML جایگاه تبلیغ میان محتوای صفحات ابزار. |

## ۴. استقرار روی Vercel

1. کد را در GitHub/GitLab قرار دهید.
2. در [vercel.com](https://vercel.com) → **Add New Project** → مخزن را انتخاب کنید. Vercel به‌طور خودکار Next.js را تشخیص می‌دهد (نیازی به تغییر Build Command نیست).
3. در بخش **Environment Variables** (برای Production و Preview) متغیرهای بالا را تنظیم کنید. در مرحله اول `NEXT_PUBLIC_SITE_URL` را خالی بگذارید و بعد از اتصال دامنه مقدار دهید.
4. Deploy بگیرید. خروجی `standalone` است و روی Vercel بدون تنظیم اضافه اجرا می‌شود.
5. هر `git push` به شاخه اصلی → Production؛ سایر شاخه‌ها → Preview.

### اتصال دامنه اختصاصی
1. در Vercel: **Settings → Domains → Add** و دامنه (مثلاً `arshamlab.com`) را وارد کنید.
2. در پنل دامنه، رکوردهای DNS طبق دستورالعمل Vercel تنظیم شود:
   - رکورد `A` روی `76.76.21.21` (برای ریشه) و/یا `CNAME` روی `cname.vercel-dns.com` (برای www).
3. HTTPS به‌طور خودکار با Let's Encrypt فعال می‌شود (نیازی به تنظیم دستی نیست).
4. **مهم:** پس از تأیید دامنه، در Vercel → Environment Variables مقدار `NEXT_PUBLIC_SITE_URL=https://arshamlab.com` را بگذارید و **Deploy مجدد** بگیرید تا Canonical، Sitemap و Open Graph به دامنه نهایی اشاره کنند.
5. در [Google Search Console](https://search.google.com/search-console) نسخه `https://arshamlab.com/sitemap.xml` را ثبت کنید.

## ۵. تبلیغات

معماری تبلیغات **ماژولار و غیرفعال به‌صورت پیش‌فرض** است:

- کامپوننت `src/components/ad-slot.tsx` دو جایگاه تعریف‌شده دارد: `homeHero` (زیر Hero صفحه اصلی) و `toolInContent` (میان محتوای صفحات ابزار، بعد از خود ابزار).
- تا وقتی `NEXT_PUBLIC_ADS_ENABLED=true` نباشد **هیچ چیزی رندر نمی‌شود** (هیچ هزینه JS/CSS).
- وقتی فعال باشد ولی کد شبکه تنظیم نشده باشد، یک Placeholder با **ارتفاع رزروشده** نمایش داده می‌شود تا Layout Shift رخ ندهد.
- جایگاه‌ها عمداً دور از دکمه‌های اصلی ابزارها قرار گرفته‌اند تا کلیک تصادفی رخ ندهد.
- هیچ نمایش، کلیک یا درآمد ساختگی در کد وجود ندارد.

**انتخاب شبکه:** برای مخاطب فارسی، گزینه‌های موجود (مثل تپسل، یکزانت یا شبکه‌های بین‌المللی) را قبل از انتشار تجاری از نظر سیاست‌ها و پرداخت بررسی کنید. برای تزریق اسکریپت شبکه تبلیغاتی، از `next/script` با `strategy="lazyOnload"` در layout یا صفحات استفاده کنید و تگ‌های `<ins>` شبکه را در متغیر `NEXT_PUBLIC_AD_*_CODE` قرار دهید؛ سپس مطابق سیاست‌های آن شبکه، صفحه سیاست حریم خصوصی را به‌روزرسانی کنید (بخش تبلیغات صفحه privacy-policy از قبل آماده این توضیح است).

## ۷. قابلیت‌های پیاده‌سازی‌شده

**۱۰ ابزار — همه واقعاً کار می‌کنند و پردازش‌شان کاملاً در مرورگر است:**

1. **شمارش متن** — کلمات/کاراکتر (با و بدون فاصله)/خطوط/پاراگراف/زمان مطالعه، زنده، کپی خلاصه
2. **حذف فاصله‌های اضافی** — ۵ گزینه قابل ترکیب، آمار حذف، خروجی زنده
3. **حذف خطوط تکراری** — حفظ ترتیب یا مرتب‌سازی الفبایی (Intl fa)، گزینه‌های مقایسه، شمارش حذف‌شده‌ها
4. **ساخت QR Code** — کتابخانه `qrcode`، پیش‌نمایش زنده، اندازه، رنگ با هشدار کنتراست WCAG، سطح ترمیم خطا، دانلود PNG
5. **محاسبه درصد** — ۴ حالت (درصدِ عدد، درصد تغییر، قیمت بعد/قبل از تخفیف) با نمایش مراحل و پذیرش ارقام فارسی
6. **اختلاف تاریخ** — احتساب/عدم احتساب روز پایانی، معادل شمسی، تفکیک هفته/ماه، دکمه «امروز»
7. **تبدیل ارقام** — فارسی↔انگلیسی و عربی→فارسی با حفظ کامل متن و جابه‌جایی سریع جهت
8. **فرمت‌کننده JSON** — زیباسازی (تورفتگی ۲/۴)، فشرده‌سازی، مرتب‌سازی بازگشتی کلیدها، خطای فارسی با خط/ستون، دانلود فایل
9. **ساخت رمز عبور** — Web Crypto API + نمونه‌گیری طردی (بدون Math.random)، تضمین حضور هر مجموعه، حذف کاراکترهای مبهم، سنجش آنتروپی
10. **محاسبه سن** — تقویم شمسی/میلادی، الگوریتم دقیق جلالی (کبیسه ۱۴۰۳ صحیح)، رد تاریخ آینده و روز ناموجود

**زیرساخت:**
- صفحه اصلی کامل (Hero + جست‌وجوی GET بدون JS، منتخب، دسته‌بندی، مزایا، CTA)
- صفحه `/tools` با جست‌وجوی زنده URL-محور و فیلتر دسته/محبوب
- هدر چسبان با جست‌وجوی مودال (Ctrl+K، نرمال‌سازی فارسی ی/ك و ارقام) و منوی موبایل
- فوتر کامل با لینک‌های دسته‌بندی و صفحات حقوقی؛ چسبان به پایین (sticky)
- صفحات درباره ما، تماس (فرم mailto شرطی به env)، سیاست حریم خصوصی و شرایط استفاده — با محتوای واقعی مطابق عملکرد سایت، بدون اطلاعات جعلی
- ۴۰۴ اختصاصی؛ بردکرامب + BreadcrumbList در همه صفحات داخلی
- دسترس‌پذیری: aria-live برای نتایج، aria-expanded برای منو، focus-visible، کنتراست، صفحه‌کلید
- اعتبارسنجی ورودی در همه ابزارها، پیام‌های خطای فارسی، سقف طول ورودی برای جلوگیری از قفل UI
- امنیت: هدرهای امنیتی (nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy)، بدون dangerouslySetInnerHTML با ورودی کاربر، بدون ذخیره‌سازی بی‌دلیل
- **۹۳ تست واحد** با `bun:test` روی همه منطق خالص (شمارش، فاصله‌ها، تکراری‌ها، ارقام، جلالی، تاریخ، درصد، رمز، JSON، رجیستری)
- TypeScript سخت‌گیرانه: `tsc --noEmit` و `eslint` بدون خطا؛ Build تولیدی موفق با prerender کامل

## ۸. موارد باقی‌مانده و محدودیت‌های شناخته‌شده

- **تبلیغات واقعی:** نیازمند حساب ناشر تأییدشده؛ جایگاه‌ها آماده است ولی کد شبکه‌ای تزریق نشده (طبق الزام، هیچ چیز ساختگی نمایش داده نمی‌شود).
- **ایمیل تماس:** تا تنظیم `NEXT_PUBLIC_CONTACT_EMAIL`، فرم تماس عمداً غیرفعال است.
- **تقویم شمسی در date-difference:** ورودی این ابزار میلادی است (معادل شمسی نمایش داده می‌شود)؛ در صورت نیاز، افزودن ورودی شمسی به این ابزار به‌سادگی با همان `lib/jalali.ts` ممکن است.
- **Lighthouse/PageSpeed:** باید روی دامنه تولیدی واقعی اجرا شود؛ در محیط توسعه اعداد معتبر نیستند.
- **فایل‌های تصویری/تبدیل فرمت:** دسته‌های «تصاویر» و «فایل» عمداً نمایش داده نمی‌شوند چون هنوز ابزار ندارند (طبق الزام «فقط دسته‌های دارای ابزار»).
- **سال کپی‌رایت فوتر:** به‌صورت ثابت (۱۴۰۵) نوشته شده؛ در نگهداری دوره‌ای به‌روزرسانی کنید (یا در آینده داینامیک شود).
- **دسته ابزارهای محبوب:** فعلاً برچسب دستی در رجیستری است؛ در آینده می‌تواند از آمار بازدید واقعی تغذیه شود (نیازمند ابزار تحلیل اختیاری).

## ۹. افزودن ابزار جدید (توسعه‌پذیری)

1. در `src/lib/tools.ts` یک ورودی به آرایه `TOOLS` اضافه کنید (اسلاگ، عنوان، توضیح متا، دسته، آیکون، کلمات کلیدی).
2. منطق خالص را در `src/lib/<domain>-utils.ts` بنویسید و در `tests/` تست اضافه کنید.
3. کامپوننت کلاینت را در `src/components/tools/<slug>-client.tsx` بسازید (از قطعات `tool-ui.tsx` استفاده کنید).
4. پوشه `src/app/tools/<slug>/page.tsx` را با الگوی صفحات فعلی بسازید: metadata از `buildToolMetadata` + `ToolPageShell` + محتوای راهنمای یکتا.
5. تمام! Sitemap، جست‌وجو، فهرست ابزارها، لینک‌های مرتبط و دسته‌بندی‌ها **به‌طور خودکار** به‌روز می‌شوند.
